# Azmuth read-only API — contract for the web dashboard

Version `v1`. Base URL: `http://127.0.0.1:8765/api/v1`

The TUI collects everything (metrics every 5 s, processes 5 s, services 30 s,
logs 15 s, diagnostics 60 s). The API only **reads** what the TUI already
has: calling it never opens an SSH session to a server, so polling is cheap.

```
VMs ──SSH──▶ Azmuth TUI (collector, SQLite) ──HTTP GET, token──▶ ASP.NET ──▶ browser
                                                                   └──▶ n8n (Telegram, AI, reports)
```

Real response examples (generated by the test suite) are in `docs/examples/`.

---

## 1. Turning it on

The API is **off by default**. In the TUI press **`A`** (or `ctrl+p` → "API: start").
The top bar shows `api: ON :8765`. Press `A` again to stop it.

- Port: `8765` (change with the setting `api_port`, 1024–65535).
- Listens on `127.0.0.1` only. ASP.NET must run on the same machine.

## 2. Authentication

Every endpoint except `/health` needs:

```
Authorization: Bearer <token>
```

The token is in `~/.config/azmuth/api-token` (file `0600`, folder `0700`,
owned by the user running Azmuth). It is created the first time the API starts.

- Rotate: `ctrl+p` → "API: rotate token". The old token stops working immediately.
- Do **not** put the token in the browser or in JavaScript. Only the ASP.NET
  server sends it (server-to-server).

C# example:

```csharp
var token = File.ReadAllText(Path.Combine(
    Environment.GetFolderPath(Environment.SpecialFolder.UserProfile), ".config/azmuth/api-token")).Trim();

var http = new HttpClient { BaseAddress = new Uri("http://127.0.0.1:8765/api/v1/") };
http.DefaultRequestHeaders.Authorization = new AuthenticationHeaderValue("Bearer", token);

var servers = await http.GetFromJsonAsync<JsonElement>("servers");
```

## 3. Security rules (what the API enforces)

| Rule | Result if broken |
|---|---|
| Only `GET` / `HEAD` | `405 method_not_allowed` — the API cannot change anything |
| Valid bearer token (constant-time compare) | `401 unauthorized` (and an `api_auth_failed` audit entry) |
| `Host` header must be `127.0.0.1`, `localhost` or `[::1]` | `421 bad_host` (blocks DNS-rebinding from web pages) |
| ≤ 600 requests / minute in total, ≤ 10 bad tokens / minute (a bad-token flood never blocks the valid token) | `429 rate_limited` |
| No CORS headers | browsers cannot call it directly |

Data protection: process command lines, log messages, audit details and
incident evidence are **redacted** before they leave Azmuth (passwords,
tokens, `Authorization` headers, private keys, `mysql -p…`, URL credentials,
AWS keys, JWTs → `[REDACTED]`). SSH keys, key paths, passwords and the
database itself are never exposed.

## 4. Conventions

- JSON, UTF-8. Times are UTC ISO-8601: `"2026-11-24T23:14:20Z"`.
- Sizes are bytes, percentages are 0–100.
- `null` means "not collected yet" (e.g. right after connecting).
- Errors always look like this:

```json
{ "error": { "code": "not_found", "message": "Server not found" } }
```

Codes: `bad_request` (400), `unauthorized` (401), `not_found` (404),
`method_not_allowed` (405), `bad_host` (421), `rate_limited` (429), `internal_error` (500).

Severities: `critical` > `error` > `warning` > `info`.
Incident status: `open` → `investigating` → `resolved` (changed only in the TUI).

## 5. Endpoints

| Endpoint | Query parameters | Use it for |
|---|---|---|
| `GET /health` | — | is Azmuth up (no token needed) |
| `GET /servers` | — | server list + state + incident count |
| `GET /servers/{name}` | — | one server: summary + current metrics + failed services |
| `GET /servers/{name}/metrics` | — | current CPU / memory / disk / load |
| `GET /servers/{name}/metrics/history` | `minutes` 1–10080 (default 60) | charts |
| `GET /servers/{name}/processes` | `sort` cpu\|mem\|rss\|pid, `limit` 1–500 (50) | top processes |
| `GET /servers/{name}/services` | `state` all\|failed\|active\|inactive | services page |
| `GET /servers/{name}/logs` | `since` epoch, `level` INFO\|WARNING\|ERROR\|CRITICAL (≥), `unit`, `q`, `limit` 1–1000 (200) | logs page |
| `GET /alerts` | — | live threshold alerts (ping, CPU, memory, disk, failed units) |
| `GET /incidents` | `server`, `status` active\|open\|investigating\|resolved\|all (active), `severity`, `limit` 1–500 (100), `created_since` epoch, `seen_since` epoch | incidents list, n8n alerts and reports |
| `GET /incidents/{id}` | — | full incident: root cause, confidence, checks, evidence |
| `GET /incidents/{id}/export` | `format` json\|markdown, `mask_ips` 0\|1 | **what n8n sends to the AI** |
| `GET /audit` | `limit` 1–1000 (100), `mask_ips` | audit page |

### `GET /servers`
```json
{ "servers": [ {
    "name": "web-srv", "host": "192.168.122.11", "port": 22,
    "connected": true,
    "ping": { "online": true, "latency_ms": 0.4 },
    "active_incidents": 2, "worst_severity": "error",
    "last_collected": { "metrics": "2026-11-24T23:14:20Z", "logs": "2026-11-24T23:14:20Z" },
    "collection_errors": {}
} ] }
```
`ping` is `null` until the first ping (every 30 s). `connected` is the SSH state.

### `GET /servers/{name}/metrics`
```json
{ "server": "web-srv", "metrics": {
    "collected_at": "2026-11-24T23:14:20Z",
    "cpu_percent": 17.0,
    "memory": { "percent": 5.9, "used_bytes": 494010368, "total_bytes": 8413396992 },
    "disk_root": { "percent": 29.0, "used_bytes": 12850286592, "total_bytes": 270553174016 },
    "load": [0.01, 0.04, 0.03], "cpus": 2, "uptime_seconds": 1140,
    "hostname": "web-srv", "os": "Ubuntu 24.04.1 LTS", "kernel": "6.8.0-49-generic" } }
```

### `GET /servers/{name}/metrics/history?minutes=60`
```json
{ "server": "web-srv", "minutes": 60, "resolution_seconds": 5,
  "samples": [ { "ts": "2026-11-24T23:14:20Z", "cpu": 17.0, "mem_percent": 5.9,
                 "disk_percent": 29.0, "load1": 0.01, "load5": 0.04, "load15": 0.03,
                 "mem_used": 494010368, "mem_total": 8413396992 } ] }
```
Recent samples are 5 seconds apart (memory); older ones, or all of them right after Azmuth restarts, are 30-second averages from
the database (kept 7 days). History starts when the server was first connected.

### `GET /servers/{name}/logs`
```json
{ "server": "web-srv", "journal_access": "full", "count": 1,
  "entries": [ { "ts": "2026-11-24T23:14:20Z", "epoch": 1795562060.0, "level": "ERROR",
                 "source": "kernel", "unit": "", "pid": null,
                 "message": "Out of memory: Killed process 1234 (java)" } ] }
```
**Live tail:** remember the last `epoch` and call again with `?since=<epoch>`
to receive only newer lines. `journal_access: "limited"` means the SSH user
is not in `systemd-journal`/`adm`, so system logs are missing.

### `GET /incidents/{id}`
```json
{ "id": "INC-0001", "server": "web-srv", "category": "memory",
  "severity": "critical", "status": "open", "cleared": false,
  "title": "mysql.service stopped: OOM killer terminated mysqld",
  "root_cause": "Memory exhaustion: the kernel's OOM killer terminated mysqld (pid 4242).",
  "confidence": "high", "confidence_reason": "systemd reported the OOM kill for mysql.service",
  "impact": "Service downtime: the killed process stopped.",
  "affected": ["mysql.service"],
  "checks": [ { "title": "Memory right now", "command": "free -h" } ],
  "first_seen": "2026-11-24T23:14:20Z", "last_seen": "2026-11-24T23:14:20Z",
  "event_count": 1, "recurring": 0, "previous_id": null,
  "evidence": [ { "ts": "2026-11-24T23:14:20Z", "source": "kernel", "unit": "",
                  "role": "cause", "message": "Out of memory: Killed process 4242 (mysqld)" } ] }
```
- `confidence` is a label with a reason, not a percentage: `high` = explicit
  link in the logs, `medium` = linked by time / last error line, `low` = cause unknown.
- `cleared: true` = the problem is no longer detected but nobody resolved it yet.
- `recurring` = how many times this same problem was resolved before.
- Checks whose title starts with `Change` modify the system; the rest are read-only.

## 6. Suggested polling

| Page | Endpoint | Every |
|---|---|---|
| Dashboard cards | `/servers`, `/alerts` | 5–10 s |
| Charts | `/servers/{name}/metrics/history?minutes=60` | 30 s (or append `/metrics` every 5 s) |
| Processes | `/servers/{name}/processes?limit=50` | 5 s |
| Services | `/servers/{name}/services` | 30 s |
| Logs | `/servers/{name}/logs?since=<last epoch>` | 15 s |
| Incidents | `/incidents` | 60 s |

The limit is 600 requests/minute shared by everything on this machine (ASP.NET + n8n); normal polling uses a small part of it.
Cache in ASP.NET and serve several browser tabs from the cache.

## 7. n8n

### 7.1 Who talks to whom

```
Azmuth TUI ──HTTP + token──▶ ASP.NET ──▶ browser
                                │
                                └──webhook──▶ n8n ──▶ Telegram / AI / e-mail
```

**Recommended:** ASP.NET is the **only** client of the Azmuth API. It
forwards what n8n needs (to an n8n webhook), or exposes a small internal
endpoint that n8n calls. The token then lives in one place, and n8n never
needs it.

**Alternative:** n8n calls the API directly. Then:

- n8n must reach `127.0.0.1:8765` **of this machine**. If n8n runs in
  Docker, `127.0.0.1` inside the container is the container itself: start
  it with `--network host` (Linux), or run n8n without Docker.
  Do **not** try to expose the API on another address: Azmuth listens on
  `127.0.0.1` only and rejects any other `Host` header (`421`).
- Store the token in an n8n **credential** (type *Header Auth*,
  name `Authorization`, value `Bearer <token>`), never inside a workflow
  (workflows get exported and shared).

### 7.2 Workflow 1 — alert on new incidents (Telegram)

1. **Schedule trigger** every 60 s.
2. `GET /incidents?status=active&created_since=<last>` where `<last>` is
   the `now` value returned by the previous run (store it with n8n
   *static data*; use `0` the first time).
3. Save the new `now` from the response for the next run.
4. For each incident with `severity` `critical` or `error` (and optionally
   `warning`), send to Telegram:
   `[{severity}] {server}: {title}` + `{root_cause}` + `confidence: {confidence}`.

Using `created_since` = the server's own `now` means no incident is missed
and none is sent twice, even if a run fails. A problem that comes back after
being resolved is a **new** incident (new id, `recurring` ≥ 1), so it is alerted again.

### 7.3 Workflow 2 — "Azmuth is offline"

Every 60 s: `GET /health` (no token needed). If it fails 3 times in a row,
send one Telegram message ("Azmuth/API not reachable"), and one more when it
answers again. A failing health check means the TUI is closed or the API was
turned off (key `A`) — **not** that a server is down.

### 7.4 Workflow 3 — AI explanation

1. Trigger: a button in the web UI (ASP.NET calls an n8n webhook with the incident id),
   or automatically for new `critical` incidents from workflow 1.
2. `GET /incidents/{id}/export?format=markdown&mask_ips=1` — secrets are
   already removed and private IPs replaced by `host-1`, `host-2`…
3. Send only that text to the model, with a prompt such as: *"Explain this
   Linux incident for a junior admin, list likely causes and safe checks.
   Do not invent facts that are not in the report."* A local model (Ollama)
   keeps the data on the machine.
4. Show the answer next to the incident, labelled **"AI suggestion — not
   verified"**. Azmuth's own root cause and confidence stay the reference.

Never send raw logs, `/logs`, `/processes` or `/audit` output to an external AI.

### 7.5 Workflow 4 — daily report

Once a day (e.g. 08:00):

- `GET /servers` — state of every server
- `GET /incidents?status=all&seen_since=<now - 86400>&limit=500` — everything active in the last 24 h
- `GET /audit?limit=500&mask_ips=1` — admin actions (filter `time` to the last 24 h)
- optional: `GET /servers/{name}/metrics/history?minutes=1440` for min / max / average CPU and memory

Format it (counts by severity, top problems, still-open incidents) and send
by Telegram or e-mail.

### 7.6 What n8n must NOT expect

- No write actions: n8n cannot restart services or resolve incidents.
  Status changes happen in the TUI only.
- No push: Azmuth does not call n8n. n8n (or ASP.NET) polls.
- Data exists only while the TUI runs with the API on. Plan for `/health` failing.
